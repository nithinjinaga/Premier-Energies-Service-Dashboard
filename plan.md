### 0.2 What "do not modify application code" means in practice

The UI cannot be restyled without editing `build_dashboard.py`, because that file *is* the frontend. The rule is
therefore applied as a boundary inside the file:

| Zone in `build_dashboard.py` | Lines (current) | Rule |
|---|---|---|
| `<style>` block | 33–185 | **Rewrite freely** |
| Body markup | 189–294 | **Restructure freely, but preserve every element `id` listed in §0.3** |
| Chart factories `mkBar / mkDonut / mkStacked / mkLines`, `Chart.defaults`, `COLORS`, heatmap colour string | 300–301, 475–510, 649–650 | **Styling options only** (colours, radius, fonts, tooltip, legend). Do not change what data is passed. |
| `buildHeaderTools()` / `syncHeaderUI()` | 321–412 | Class names / where elements mount may change; month-selection logic, shift-click, search wiring must not |
| Data state, filters, `applyAll`, `isDefect`, KPI maths, `groupSum`, aggregation, Top-3 logic, table sort/paging, `fetch('data.json')` | everything else | **Do not touch** |
| Python wrapper (lines 1–23, 761–764) | | **Do not touch** |

Anything in this plan that needs *new* JS is labelled **[NEW JS]** and listed separately in §5 so it can be approved
or dropped independently. Phase 1 requires none of it.

## 1. Weak points of this redesign (read before starting)

1. **Shopeers is a multi-page product; this is one page.** Its sidebar implies routing. We use jump-links to page
   sections. That's honest but less "app-like" than the reference. Real pages (e.g. a separate Records view) are a JS
   change, not a restyle — out of scope.
2. **Density mismatch.** Shopeers shows 4 KPIs + 2 charts + 1 table. We have 4 KPIs + 11 charts + heatmap + 9-column
   table. With Shopeers spacing the page gets ~30–40 % longer. Mitigation: 8/4 grid pairing, progress-list instead of
   one bar chart, slightly shorter chart boxes (design.md §6.2). Do not drop charts — each carries a business question.
3. **Trend chips look premium but need logic we don't have.** Shopeers' "▲ 15.5 % vs last period" requires computing
   the previous period. Phase 1 shows existing status text in the chip slot; real deltas are [NEW JS] Phase 2, with
   **inverted polarity for TAT and WIP** (a falling TAT is good — a naive copy would paint it red).
4. **Refresh destroys and rebuilds every chart** (`charts[id].destroy()` then `new Chart`). Any entry animation will
   replay on every filter change *and on every window resize* (resize handler calls `refresh()`). Premium-feeling
   transitions need `chart.update()` instead — a JS change. Plan: keep destroy/rebuild, shorten animation, disable it
   for resize-triggered refreshes only if approved (§7).
5. **Colour-by-index bug risk.** Category colours are assigned by position in the filtered list
   (`COLORS[i]`), so a category's colour changes when another drops out. A fixed name→colour map is cleaner but is a
   small JS change [NEW JS, optional]. Without it, design.md §10.5 cannot be fully honoured.
6. **Figma values are estimated.** The API was rate-limited; all tokens come from PNG sampling with an assumed ÷1.3
   scale. Expect a visual tuning pass after Phase 1.
7. **Inter from Google Fonts adds a network dependency** to a dashboard that currently has only one CDN (Chart.js).
   Acceptable for Vercel hosting; fall back to system font if blocked.

## 7. Responsive considerations

- **Breakpoints:** 1440 · 1280 · 1024 · 768 · 480 (design.md §11). Current code uses 768/480 only; `isMobile()` in JS
  uses 768 for chart legend placement — keep 768 as the legend switch so CSS and JS agree.
- **Sidebar:** expanded ≥1280, icon rail 1024–1279, off-canvas drawer <1024 (checkbox hack: `#nav-toggle:checked ~ .sidebar`).
- **Grid:** spans collapse `col-8/col-4 → col-12` below 1024; `col-6` → `col-12` below 1024; KPI 4 → 2 (<1024) → 1 (<480).
- **Charts:** `maintainAspectRatio:false` already; only chartbox heights change. Horizontal-bar charts (Pareto,
  States) need ≥ 260 px height on mobile for 10–12 labels.
- **Table:** horizontal scroll with sticky first column; hide 2 low-value columns < 480 via `nth-child` CSS.
- **Heatmap:** already `overflow:auto`; add sticky row-label column.
- **Month popover:** 340 px fixed width overflows < 380 px screens — make it `width:min(340px, calc(100vw - 24px))`
  and anchor left on mobile.
- **Touch:** controls ≥ 44 px below 1024; selects 16 px font on iOS to stop zoom-on-focus (current 14 px triggers zoom).
- **Resize performance:** the resize handler rebuilds all 11 charts after 250 ms; sidebar rail/drawer transitions will
  trigger it. Acceptable; noted in §1.4.

## 8. Animation & interaction recommendations

| Element | Interaction | Spec |
|---|---|---|
| Nav item | hover / active | bg + colour, `150ms ease` |
| Sidebar rail / drawer | open-close | `transform: translateX` 240 ms `cubic-bezier(.4,0,.2,1)`; scrim opacity 200 ms |
| Jump links | click | `html{scroll-behavior:smooth}`; disabled under reduced-motion |
| Cards | hover | border-colour + shadow-2, 200 ms; **no** translateY (11 charts lifting looks noisy) |
| Buttons | press | `scale(.98)` 100 ms |
| Popover / dropdown / filter sheet | open | opacity 0→1 + `translateY(-4px)→0` (sheet: `translateY(100%)→0`), 160 ms ease-out |
| Search pill (mobile expand) | open | keep existing width transition 280 ms |
| KPI values | on refresh | Optional count-up 400 ms **[NEW JS]**; skip in Phase 1 |
| Charts | build | `Chart.defaults.animation.duration = 450`, easing `easeOutQuart`. Because charts are rebuilt on every filter change, keep it short. |
| Charts | hover | tooltip dark, line hover point 5 px, bar hover `hoverBackgroundColor` = primary-600 |
| Table rows | hover | bg 120 ms |
| Loader | progress | existing logo-fill + new 4 px bar, 300 ms height/width transition |
| Focus | keyboard | `:focus-visible` ring on all controls |
| Reduced motion | `@media (prefers-reduced-motion: reduce)` | disable transitions, smooth scroll, and set `Chart.defaults.animation=false` (one-line read of `matchMedia` — options-only) |

## 9. Verification checklist (per phase)

1. `python build_dashboard.py` exits 0 and prints "Dashboard written".
2. **Id contract:** every id in §0.3 present exactly once in `index.html`:
   ```bash
   for id in months march-note filterToggle f-customer f-custname f-category f-subcat f-state f-status f-plant \
     f-resolution reset k-closed-label k-closed k-closed-note k-closure k-closure-note k-tat k-tat-note k-wip \
     k-wip-note top3badges chTop3 chCat chPareto chCust chPlant chStatus chState chTATtrend chBatch chMonthly \
     chCatTrend heatmap tcount search tbl tbody pginfo pgjump pgjumpbtn prev next loading logo-fill load-pct; do
     n=$(grep -o "id=\"$id\"" index.html | wc -l); [ "$n" = 1 ] || echo "MISSING/DUP: $id ($n)"; done
   ```
3. Browser console: zero errors on load.
4. **Functional smoke (must match baseline numbers exactly):** KPI values for All months; single month (Aug-26);
   shift-select 3 months; each of the 8 filters; customer type ↔ name cascade; category → sub-category cascade;
   reset; header search + table search sync; table sort each column; pager prev/next/jump; March note appears when
   Mar-26 selected.
5. Screenshots at 1440 / 1024 / 768 / 390 compared against `design reference/Shopeers dashboard — editable.png`.
6. Lighthouse accessibility ≥ 90; contrast: text-3 `#85858f` on #fff is ~3.6:1 — **fails AA for body text**. Use
   text-3 only for ≥ 12 px labels/captions that aren't essential, or darken to `#6b6b75` (≈ 5:1). Decide during
   Phase 1 tuning.
